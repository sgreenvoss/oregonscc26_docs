Two types of input to the model: idealized initial conditions and real data initial conditions.
- **real data**: intended to represent the state of the atmosphere at some specific point in time over some specific part of the real earth surface
WPS: used to configure real-data simulations

## geogrid
Does geographical processing on WRF model grid.
Used to define:
- map projection (used to flatten curved earth surface)
	- can use four different projections
	- for global domain, must use lat-long
- geographic location of domains
- dimensions of domains
- horizontal resolution of domains (number of grid points)
Given those, provides values for static (time-invariant) fields at each model grid point. 

### Projections
Each projection distorts distance differently. The maximum stable timestep in WRF depends on the map scale factor (available in geogrid output files: MAPFAC_M)
- Lambert conformal conic
	- good for mid-latitudes, can't contain either pole.
	- domain can't be periodic in west-east direction (where flow going out east domain comes back in west domain, e.g.)
- Mercator projection
	- good for low-latitudes
	- can use for periodic domain in west-east direction ("channel" domain)
- Polar stereographic
	- good for high-latitudes, especially poles
- Cylindrical equidistant
	- covers entire earth surface

### Defining model domains
- MAP_PROJ: lambert, mercator, polar, lat-lon
- TRUELAT1: first true latitude 
- TRUELAT2 (for lambert)
- POLE_LAT, POLE_LON (for lat-lon)
- STAND_LON: longitude line that's parallel to the y-axis
all reside in namelist.wps
- Define area covered (dims, loc) by:
	- REF_LAT, REF_LON: by default, center of domain
	- DX, DY: grid distance where map factor = 1
	- E_WE, E_SN: velocity points in each dir

Writes output (parameters defining each domain, interpolated static fields) into geo_em.d0{n}.nc where n is the domain ID number

## ungrib
Converts "grib" datasets into an easily-processable format.

GRIB: file format, standing for Generally Regularly-distributed Information in Binary
- fields are compressed lossily
- fields only identified by code numbers to be referenced against an external table. 

ungrib reads, extracts fields, derives fields, writes requested fields to an intermediate file format.

Uses Vtables to know which fields to extract
- files that give the grib codes for fields to be extracted
- one table for each source of data
- if a data source has no existing Vtable, you have to create it yourself

If a data source is not in GRIB format, you can write to the intermediate format directly.

## metgrid
Combines output from geogrid and ungrib: horizontally interpolates meteorological data (from ungrib) to simulation domains (defined by geogrid).

Masked fields - may only have valid data at some grid points. during interpolation, needs to know which points are invalid. 
- can either use separate mask field or rely on special values in the field to identify masked grid points.
- common fields that need masking are SST, soil moisture, soil temperature

does wind vector rotation: transforms from source grid to WRF simulation grid

can specify fields as constants using CONSTANTS_NAME
